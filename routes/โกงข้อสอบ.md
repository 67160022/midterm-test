WK01 — HTTP & Express Fundamentals

คำถามท้ายบทครอบคลุม HTTP แบบ stateless, lifecycle, HTTP methods และ status codes

ข้อ 1 HTTP เป็น Stateless คืออะไร

HTTP เป็น Stateless หมายความว่า Server จะไม่จดจำสถานะหรือข้อมูลของ Request ก่อนหน้าโดยอัตโนมัติ แต่ละ Request ต้องมีข้อมูลที่จำเป็นสำหรับการประมวลผลด้วยตัวเอง

ผลกระทบต่อ Backend:

หากผู้ใช้ Login แล้ว Server ต้องใช้กลไกเพิ่มเติมในการจดจำตัวตน เช่น

Cookie
Session
Token เช่น JWT

ตัวอย่าง ผู้ใช้ Login สำเร็จแล้ว Request ถัดไปต้องส่ง Token มาด้วย เพราะ Server ไม่ได้จำโดยอัตโนมัติว่าผู้ใช้นี้เคย Login มาก่อน

ข้อ 2 จงเรียงลำดับ HTTP Lifecycle

ลำดับหลักคือ

DNS Resolution — แปลง Domain Name เป็น IP Address
TCP Connection — สร้างการเชื่อมต่อระหว่าง Client และ Server
TLS Handshake — หากเป็น HTTPS จะมีการเข้ารหัส
HTTP Request — Client ส่ง Method, URL, Header และ Body
Server Processing — Server ประมวลผลคำขอ เช่น ตรวจสอบข้อมูลหรือ Query Database
HTTP Response — Server ส่ง Status Code, Header และ Body กลับ
Connection ปิดหรือ Keep-Alive — เลือกปิดหรือใช้ Connection เดิมต่อ

ข้อ 3 GET, POST, PUT, DELETE มี Idempotent หรือไม่
Method Idempotent เหตุผล
GET ใช่ เรียกซ้ำกี่ครั้งก็อ่านข้อมูลเดิม ไม่เปลี่ยนสถานะ
POST ไม่ใช่ เรียกซ้ำอาจสร้างข้อมูลใหม่หลายรายการ
PUT ใช่ ส่งข้อมูลเดิมซ้ำ ผลลัพธ์สุดท้ายเหมือนเดิม
DELETE ใช่ ลบครั้งแรกข้อมูลหาย ครั้งต่อไปก็ไม่มีข้อมูลให้ลบ ผลลัพธ์สุดท้ายยังเหมือนเดิม
ข้อ 4 สร้างข้อมูลใหม่สำเร็จควรใช้ Status Code อะไร

ควรใช้

201 Created

เพราะ HTTP Status Code นี้สื่ออย่างชัดเจนว่า Request สำเร็จและเกิด Resource ใหม่ขึ้น

ไม่ควรใช้ 200 OK เพราะแม้จะหมายถึงสำเร็จเหมือนกัน แต่ 201 Created มีความหมายเฉพาะเจาะจงกว่าและตรงกับสถานการณ์
